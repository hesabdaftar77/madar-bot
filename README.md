# مدار پرو — ربات CRM چنددفتری برای مشاوران املاک

ربات تلگرام (python-telegram-bot 20+، SQLite، jdatetime، bcrypt) با رابط کاملاً فارسی.

## ساختار پوشه‌ها
```
madar_pro/
├─ bot/
│  ├─ main.py        شروع ربات + زمان‌بندی jobها
│  ├─ config.py      متغیرهای محیطی
│  ├─ db.py          اسکیمای کامل + توابع پارامتری (?)
│  ├─ seed.py        انواع ملک/معامله، فیلدها، وزن‌های تطبیق (ورودی جدول‌های تنظیمات)
│  ├─ auth.py        رمز سازنده (bcrypt)، لایسنس، اعضا
│  ├─ guard.py       decorator مرکزی نقش/دفتر
│  ├─ fields.py      موتور فرم پویا
│  ├─ records.py     فایل/مشتری/بازدید/یادداشت (همه با office_id)
│  ├─ matching.py    تطبیق درصدی
│  ├─ parser.py      استخراج فایل از متن آزاد
│  ├─ ads.py         متن آگهی دیوار/تلگرام
│  ├─ reports.py     گزارش ماهانه
│  ├─ chatdb.py      چت روم + آرشیو ماهانه
│  ├─ offices.py     حذف دفتر + خروجی
│  ├─ excel_io.py    درون‌ریزی/بیرون‌ریزی
│  ├─ jobs.py        یادآور صبح، آرشیو چت، بک‌آپ
│  └─ handlers/      router, form, views, actions, admin, chatroom, io_h, common
├─ tests/            تست‌های دودی
├─ requirements.txt  .env.example  Procfile  railway.json  .python-version
```

## اسکیمای دیتابیس
- **main.db**: `settings`, `offices`, `users`, `licenses`, `property_types`, `deal_types`, `field_defs`, `match_weights`, `listings`, `customers`, `visits`, `notes`, `chat_archives` — همهٔ جدول‌های داده `office_id` دارند.
- **chats/office_<id>.db**: یک دیتابیس چت جدا برای هر دفتر (`messages`).
- شمارهٔ فایل و مشتری برای هر دفتر از ۱ شروع می‌شود (`no`).

## اجرای محلی
```bash
python -m venv .venv && source .venv/bin/activate     # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # BOT_TOKEN و SUPER_LICENSE را پر کنید
python -m bot.main
```
در تلگرام: `/start` ← لایسنس را بفرستید. رمز سازنده = مقدار `SUPER_LICENSE` (ورود با آن، پنل سازنده را نشان می‌دهد).

## دیپلوی روی Railway (قدم‌به‌قدم)
1. پروژه را در یک ریپوی خصوصی GitHub بگذارید (`.env` و `data/` در `.gitignore` هستند).
2. Railway ← New Project ← Deploy from GitHub ← همین ریپو. (`Procfile`/`railway.json` سرویس را به‌صورت worker اجرا می‌کنند؛ پورت لازم نیست.)
3. تب **Variables**: `BOT_TOKEN`, `SUPER_LICENSE`, `DATA_DIR=/data`، و اختیاری: `BACKUP_CHANNEL_ID`, `BACKUP_DB_DAILY`, `MORNING_HOUR`, `MAX_AGENTS_PER_OFFICE`.
4. **Volume**: Settings ← Volumes ← New Volume ← Mount path: `/data` (بدون Volume با هر دیپلوی همهٔ داده‌ها پاک می‌شود).
5. کانال بک‌آپ: یک کانال **خصوصی** بسازید، ربات را ادمین کنید، آیدی (مثل `-100…`) را در `BACKUP_CHANNEL_ID` بگذارید.
6. Deploy. لاگ باید «Application started» نشان دهد. فقط یک نمونه (replica) اجرا شود.

## مدیریت رمز سازنده
- اولین اجرا: `SUPER_LICENSE` با bcrypt هش و در دیتابیس ذخیره می‌شود؛ بعد از آن فقط دیتابیس چک می‌شود (تغییر متغیر اثری ندارد).
- تغییر: پنل سازنده ← «🔑 تغییر رمز» (رمز فعلی ← جدید ← تأیید؛ فوراً اعمال، پیام‌ها پاک می‌شوند، حداقل ۱۲ کاراکتر؛ ورودهای دیگرِ سازنده باطل می‌شوند).
- فراموشی: `SUPER_LICENSE=<رمز جدید>` و `RESET_SUPER_LICENSE=1` بگذارید، یک‌بار ری‌استارت، سپس `RESET_SUPER_LICENSE` را حذف کنید.
- رمز هرگز لاگ یا نمایش داده نمی‌شود (لاگ httpx هم خاموش است تا URL توکن ظاهر نشود). ورود اشتباه فقط «لایسنس نامعتبر است» می‌دهد.

## سطوح کاربری
- **سازنده**: لایسنس مدیر می‌سازد، همهٔ دفترها/کاربران را می‌بیند، کاربر یا دفتر را حذف می‌کند، وارد هر دفتر می‌شود (فقط مشاهده)، آرشیو «دفاتر حذف‌شده»، **درون‌ریزی** و **بیرون‌ریزی** فقط برای او. در هیچ لیست/چت/شمارشی دیده نمی‌شود و دستورهایش برای دیگران بی‌پاسخ است.
- **مدیر دفتر**: لایسنس مشاور می‌سازد (سقف `MAX_AGENTS_PER_OFFICE`)، مشاورها را حذف می‌کند (فایل‌هایشان می‌ماند) و همهٔ امکانات مشاور را دارد.
- **مشاور**: همهٔ فایل‌ها/مشتری‌های دفتر خودش با تمام اطلاعات.
- لایسنس‌ها: `secrets.token_urlsafe(32)`، فقط هش SHA-256 ذخیره می‌شود، یک‌بارمصرف (مصرف اتمیک)، با نقش/دفتر/سازنده/تاریخ ثبت.

## فرم پویا — افزودن نوع/فیلد بدون تغییر کد
همه چیز در جدول‌های `property_types`, `deal_types`, `field_defs`, `match_weights` است (SQLite). نمونه:
```sql
-- نوع ملک جدید
INSERT INTO property_types(code,title,sort) VALUES('parking','پارکینگ',99);
-- فیلد جدید برای آن (ابتدا dtype: text,int,decimal,money,enum,multi,bool,date,phone)
INSERT INTO field_defs(entity,code,title,dtype,required,scope_kind,scope_code,sort)
VALUES('listing','capacity','ظرفیت (خودرو)','int',1,'property','parking',900);
-- وزن تطبیق
INSERT INTO match_weights(property_type,criterion,weight,mandatory) VALUES('parking','budget',50,0),('parking','range',50,0);
```
`scope_kind`: `common` (همه)، `property`/`deal` (با `scope_code`)، `tail` (انتهای فرم). `excl_props`/`excl_deals` برای حذف فیلد مشترک از برخی انواع. فیلدهای سازگار با ستون‌های هسته (مثل `price`) در ستون ذخیره می‌شوند و بقیه در `data` (JSON).
معیارهای تطبیق پشتیبانی‌شده: `budget, range, area, rooms, amenities, date, frontage, usage, land_use, deed, water_source`.

## تطبیق
فقط فایل و مشتری هم‌نوع (نوع ملک و معامله). معیارهایی که مشتری برای آن‌ها چیزی نگفته یا فایل داده ندارد از مخرج حذف می‌شوند. بودجه: داخل بودجه ۱۰۰٪، تا ۱۰٪ بالاتر نصف، بیشتر صفر (برای رهن‌واجاره: رهن و در صورت ثبت، اجاره). معیار «ضروری» (mandatory) درصد ندارد و نبودنش فایل را حذف می‌کند (پیش‌فرض: کاربری و سند زمین). «امکانات الزامی» مشتری طبق جدول وزن، درصدی است؛ برای سخت‌گیرانه‌کردن، `mandatory=1` بگذارید. آستانه فقط مضرب ۱۰ (۴۰–۱۰۰)؛ عدد تایپ‌شده گرد و اعلام می‌شود. 🟢 ≥۸۰، 🟡 ۶۰–۷۹، 🟠 زیر ۶۰ (فقط وقتی آستانه پایین‌تر باشد) همراه مغایرت‌ها. تطبیق دوطرفه خودکار: فایل جدید ← تعداد مشتری‌های بالای آستانه (+ اطلاع به مشاور پیگیر)، مشتری جدید ← فایل‌های مناسب.

## درون‌ریزی انبوه (فقط سازنده)
«📥 درون‌ریزی» ← «📘 راهنما» / «📄 دریافت قالب اکسل» (۵۶ برگه: `f_<نوع‌ملک>_<نوع‌معامله>` برای فایل و `c_...` برای مشتری، مثل `f_apartment_sale`) ← انتخاب دفتر مقصد ← ارسال .xlsx. ردیف ۱ کد ستون، ردیف ۲ توضیح فارسی، داده از ردیف ۳. ربات اول اعتبارسنجی و گزارش خطای هر ردیف را می‌دهد؛ با «ثبت» فقط ردیف‌های معتبر ثبت می‌شوند.

## بیرون‌ریزی (فقط سازنده)
«📤 بیرون‌ریزی» ← همهٔ دفترها یا یک دفتر ← zip شامل `data.xlsx` (فایل‌ها، مشتری‌ها، اعضا، بازدید، یادداشت، چت…)، `data.json` و آرشیو txt چت‌ها.

## چت روم و آرشیو ماهانه
دکمهٔ «💬 چت روم» همهٔ پیام‌های ماه شمسی جاری را (در چند پیام) نشان می‌دهد؛ پیام هر عضو برای بقیه ارسال و ذخیره می‌شود (متن؛ برای عکس/فایل فقط `file_id`؛ ارجاع با `#ف۱۲` یا `#م۵`). هر شب ۰۰:۰۵ (و یک‌بار پس از هر راه‌اندازی، برای جبران خاموشی) ماه‌های گذشته: خروج از دیتابیس چت ← ذخیره در `شهریور_۱۴۰۵.txt` ← حذف از دیتابیس ← ارسال به کانال بک‌آپ (در صورت شکست، شب بعد دوباره). «📁 آرشیو چت‌ها» فایل هر ماه را می‌فرستد.

## حذف
- دفتر: ذخیره در پوشهٔ «دفاتر حذف‌شده» (JSON + Excel + آرشیو چت) ← پاک‌شدن داده‌ها ← ابطال لایسنس‌ها. اگر ذخیره شکست بخورد هیچ چیز پاک نمی‌شود.
- مشاور: دسترسی قطع، فایل‌ها برای دفتر می‌ماند، پیگیری‌های او بدون مسئول می‌شود.

## یادآورها
۰۸:۰۰ هر روز (`MORNING_HOUR`): مشتری‌های بدون پیگیری ۳ روز، موعد «پیگیری بعدی»، نیاز نزدیک، و قرارداد اجاره‌هایی که تا ۶۰ روز دیگر سررسید می‌شوند (سررسید = «تاریخ تخلیه»). دکمه «📞 امروز» همین را دستی نشان می‌دهد.

## دستورها
`/فایل ۱۲`، `/مشتری رضا`، `/تطبیق` [نام] — معادل انگلیسی: `/file` `/customer` `/match` (تلگرام دستور فارسی را در منوی دستورها نمی‌پذیرد؛ تایپ دستی فارسی کار می‌کند).

## توضیحات و محدودیت‌ها
- سازنده داخل دفتر فقط‌مشاهده است (ثبت/ویرایش ندارد تا نامش در داده‌ها نیاید).
- وضعیت گفتگو (فرم نیمه‌کاره) در حافظه است؛ با ری‌استارت ربات فرم نیمه‌کاره از اول شروع می‌شود، داده‌های ثبت‌شده امن‌اند.
- استخراج متن آگهی قاعده‌محور است (بدون سرویس بیرونی) و همیشه قبل از ثبت برای تأیید نشان داده می‌شود.
- بخش مالی (کمیسیون/درآمد) ساخته نشده است.
- تغییر نوع ملک/معامله یک فایل بعد از ثبت ممکن نیست (ثبت مجدد کنید).
